# پروژهٔ تشخیص سبک موسیقی

این پروژه دربارهٔ این است که ببینیم آیا می‌شود با استفاده از ویژگی‌های یک فایل صوتی، سبک موسیقی آن را پیش‌بینی کرد یا نه. برای شروع، یک مدل پایه در نظر گرفته‌ام که از ویژگی‌هایی مثل MFCC و چند ویژگی سادهٔ صوتی استفاده می‌کند و بعد نتیجه را با برچسب‌های سبک مقایسه می‌کند.

> **وضعیت فعلی:** ساختار و کد اولیه آماده است، اما هنوز دیتاست واقعی پروژه در پوشهٔ `data/raw` قرار نگرفته و نتیجهٔ نهایی مدل محاسبه نشده است. بعد از مشخص‌شدن دیتاست، منبع، مجوز استفاده و نام سبک‌های آن را اینجا ثبت می‌کنم.

## تعریف مسئله

ورودی برنامه یک فایل صوتی است و خروجی آن یکی از سبک‌هایی است که در داده‌های آموزشی وجود دارد. برای نمونه، اگر پوشه‌های داده شامل `rock` و `jazz` باشند، همین نام‌ها به‌عنوان برچسب استفاده می‌شوند. برنامه از روی صوت ویژگی عددی می‌سازد و با استفاده از آن‌ها یک طبقه‌بند آموزش می‌دهد.

در این مرحله از ویژگی‌های MFCC و چند ویژگی خلاصه‌شدهٔ صوت استفاده شده است. مدل پایهٔ فعلی Logistic Regression است. این انتخاب برای شروع مناسب است، اما به معنی بهترین مدل ممکن نیست و باید با روش‌های دیگر مقایسه شود.

## PEAS

| بخش | توضیح برای این پروژه |
|---|---|
| **Performance Measure — معیار عملکرد** | معیار اصلی Macro-F1 روی دادهٔ آزمون است تا عملکرد روی سبک‌های مختلف جداگانه دیده شود. Accuracy، F1 هر کلاس و ماتریس درهم‌ریختگی هم برای بررسی بهتر گزارش می‌شوند. |
| **Environment — محیط** | فایل‌های صوتی به‌همراه برچسب سبک. کد فعلی انتظار دارد فایل‌ها در پوشه‌هایی به شکل `data/raw/نام‌سبک/فایل‌صوتی` باشند. |
| **Actuators — عملگرها** | برنامه سبک پیش‌بینی‌شده و امتیازهای کلاس‌ها را برمی‌گرداند. در کاربرد واقعی، نتیجه می‌تواند برای کاربر نمایش داده شود یا برای بررسی انسانی فرستاده شود. |
| **Sensors — حسگرها** | برنامه فایل صوتی را می‌خواند و از موج صدا ویژگی‌هایی مثل MFCC، انرژی RMS، نرخ عبور از صفر و ویژگی‌های طیفی استخراج می‌کند. برچسب سبک برای آموزش از دادهٔ برچسب‌خورده می‌آید. |

## ویژگی‌های محیط مسئله

| ویژگی | دسته‌بندی | دلیل |
|---|---|---|
| مشاهده‌پذیری | جزئی | برنامه فقط سیگنال صوتی را دریافت می‌کند؛ سبک واقعی مستقیماً از روی موج صدا معلوم نیست و باید پیش‌بینی شود. |
| قطعیت | تصادفی | داده‌ها و تقسیم train/test می‌توانند متفاوت باشند. با ثابت‌کردن seed می‌توان بعضی اجراها را تکرار کرد. |
| توالی | ترتیبی | فایل صوتی در طول زمان تغییر می‌کند. در نسخهٔ فعلی ویژگی‌ها از کل قطعه خلاصه می‌شوند، بنابراین بخشی از ترتیب زمانی از بین می‌رود. |
| پویایی | ایستا در هر اجرا | فایل هنگام پردازش تغییر نمی‌کند؛ اما اگر داده‌های جدید اضافه شوند، ترکیب داده‌ها و عملکرد مدل ممکن است تغییر کند. |
| گسسته یا پیوسته | ترکیبی | سیگنال صوتی نمونه‌برداری‌شده و ویژگی‌های عددی است؛ خروجی مدل یکی از برچسب‌های گسستهٔ سبک است. |
| تعداد عامل‌ها | تک‌عاملی | یک برنامه پیش‌بینی انجام می‌دهد و عامل رقیب یا همکار دیگری در مسئله وجود ندارد. |

## ارزیابی مدل

معیار اصلی **Macro-F1** است، چون میانگین عملکرد کلاس‌ها را می‌سنجد و فقط به کلاس‌های پرتعداد تکیه نمی‌کند. Accuracy، گزارش هر کلاس و ماتریس درهم‌ریختگی هم در خروجی ثبت می‌شوند.

در کد فعلی، تقسیم داده به شکل stratified تصادفی انجام می‌شود. برای ارزیابی دقیق‌تر، بهتر است اطلاعات هنرمند یا آلبوم در دسترس باشد و قطعات یک هنرمند بین آموزش و آزمون پخش نشوند؛ در غیر این صورت ممکن است امتیاز آزمون بیش از حد خوش‌بینانه باشد. تا وقتی دیتاست واقعی وارد نشده، عددی به‌عنوان نتیجهٔ پروژه گزارش نمی‌کنم.

## آماده‌سازی داده

ساختار پوشه‌ها باید شبیه این باشد:

```text
data/raw/
├── jazz/
│   ├── track_01.wav
│   └── track_02.wav
└── rock/
    ├── track_01.wav
    └── track_02.wav
```

هر پوشه نام یک سبک است. فرمت‌های صوتی پشتیبانی‌شده در کد شامل WAV، MP3، FLAC، OGG و M4A هستند. پیش از استفاده، منبع داده و مجوز آن را بررسی و در این README ثبت می‌کنم. فایل‌های صوتی در `.gitignore` قرار گرفته‌اند و به‌صورت پیش‌فرض وارد Git نمی‌شوند.

## نصب و اجرا

ابتدا در پوشهٔ پروژه محیط مجازی بسازید و وابستگی‌ها را نصب کنید:

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

برای بررسی محیط، فایل `check_env.ipynb` را در Jupyter باز کنید و سلول‌ها را از ابتدا اجرا کنید. در آن، نسخهٔ Python، مسیر اجرای آن و نسخهٔ کتابخانه‌هایی مثل NumPy و Matplotlib چاپ می‌شود. خروجی اجرای واقعی را ذخیره کنید.

بعد از قرار دادن داده در `data/raw`:

```bash
python -m src.train --data data/raw --output artifacts
```

آزمون سادهٔ کد:

```bash
python -m unittest discover -s tests -v
```

## فایل‌های پروژه

- `check_env.ipynb` — ثبت اطلاعات محیط پایتون و آزمایش سادهٔ کتابخانه‌ها
- `notes/risks.md` — معیارها، ریسک‌ها و محدودیت‌های فعلی
- `src/features.py` — خواندن فایل صوتی و استخراج ویژگی‌ها
- `src/model.py` — ساخت مدل پایه
- `src/train.py` — آموزش و ارزیابی مدل
- `tests/` — آزمون‌های پایه
- `requirements.txt` و `environment.yml` — وابستگی‌های پروژه
